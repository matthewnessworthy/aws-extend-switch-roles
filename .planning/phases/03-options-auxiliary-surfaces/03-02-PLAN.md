## Known Limitations

**Phase 3 → Phase 4 transitional regression (ACCEPTED):** After Phase 3 removes the `.darkMode` class toggle from `options.js` (lines ~194–198 and ~220–222), clicking a Visual Mode radio button will write the new value to `chrome.storage.sync` but will produce **no immediate visual change on the options page** — the page must be reloaded to apply the new theme.

This is a deliberate, one-phase regression. Before Phase 3, the page repaints immediately via the `.darkMode` class toggle. After Phase 3, the pre-paint `theme-init.js` (Phase 1) already sets `data-theme` on `<html>` from `localStorage` on load — so the page always loads in the correct theme. But the Visual Mode radio's live-repaint path is intentionally deferred.

Phase 4 (THM-02/THM-04) restores live repaint via `data-theme` writeback + `storage.onChanged`. **Do not flag the Visual Mode radio producing no immediate repaint as a bug during Phase 3 review.** It is working as designed.
