  <action>
Create test/preview/index.html as the Playwright navigation target and visual contract for Phases 2-3.

The page is served by Playwright at chrome-extension://${extensionId}/preview/index.html (the build copies test/preview/ into test/extension/preview/). Paths in the page are therefore relative from test/extension/preview/ — pointing up to test/extension/js/ and test/extension/css/.

1. HEAD structure (the same wiring that will be on all 5 production pages — validates the chain end-to-end):
   - DOCTYPE html, meta charset="UTF-8", descriptive title ("AESR Design System Preview")
   - script src="../js/theme-init.js" (non-module, no type attribute) — FIRST head child (per D-01; see PATTERNS.md head wiring order)
   - link rel="stylesheet" href="../css/tokens.css"
   - link rel="stylesheet" href="../css/base.css"
   - link rel="stylesheet" href="../css/components.css"
   - script src="preview.js" — at the END of body (after all body content); this is the external toggle wiring

2. BODY structure — one section per component shell category. Each section has a data-section attribute and a visible heading. Include all shells required by ROADMAP SC2:
   - Theme switcher UI: two buttons with id="btn-light" and id="btn-dark", and one button with id="btn-auto". These buttons have NO onclick attributes. Their click behavior is wired by preview.js (see below).
   - Buttons: primary button shell (.aesr-btn .aesr-btn--primary), normal/secondary button shell (.aesr-btn .aesr-btn--normal)
   - Inputs: text input (.aesr-input), textarea (.aesr-textarea), select (.aesr-select)
   - Controls: checkbox (.aesr-checkbox), radio (.aesr-radio)
   - Role-list item shell (.aesr-role-item): contains account-id span (.aesr-role-item__account) and role-name span (.aesr-role-item__name)
   - Pane/container shell (.aesr-pane)
   - Divider (.aesr-divider)
   - Empty-state shell (.aesr-state-empty): heading slot (.aesr-state-empty__heading) + body slot (.aesr-state-empty__body)
   - Loading-state shell (.aesr-state-loading): body slot (.aesr-state-loading__body)
   - Error/alert shell (.aesr-alert .aesr-alert--error): heading slot (.aesr-alert__heading) + body slot (.aesr-alert__body)
   - A tokenized element for SC1 computed-style assertion: div id="token-probe" with style="background: var(--color-bg-layout); color: var(--color-text-body)" — this is the element the spec uses to verify token values differ between light and dark.

3. Do NOT put any inline onclick= or onanything= attributes on any element. The preview page is served from chrome-extension://, so MV3 script-src 'self' blocks all inline event handlers. All toggle logic lives in preview.js.

4. Place <script src="preview.js"></script> as the last child of <body> (after all content elements). This path is correct: the page is at preview/index.html and preview.js is a sibling at preview/preview.js, so the relative path is just "preview.js".

5. Stub text content (e.g. "Primary", "Normal", "Submit", "Select…", "Empty state heading", "No items found", "Loading…", "Error heading", "Something went wrong") — enough for the preview to be visually useful. Concrete production copy is Phases 2-3.

This file must NOT use type="module", import/export, or any inline event handler wiring. It is a plain script that queries by ID after the DOM is ready (loading at end of body ensures the elements exist).

   Action:

   - Click #btn-dark to set data-theme="dark"
   - Read computed background-color of #token-probe

   - Assert the two values are NOT equal
   Use: await page.locator('#btn-dark').click(), then page.locator('#token-probe').evaluate(el => getComputedStyle(el).backgroundColor)

2. SC2 — component shells render in both themes (FND-01):
   Name: "SC2: component shells visible in both themes"
   Action:
   - Set light theme via #btn-light
   - Assert .aesr-btn.aesr-btn--primary is visible
   - Assert .aesr-pane is visible
   - Set dark theme via #btn-dark
   - Assert .aesr-btn.aesr-btn--primary is still visible
   - Assert .aesr-state-empty is visible
   Use page.locator('.aesr-btn.aesr-btn--primary').isVisible()

3. SC3-CSP — no CSP violations on load (THM-03):
   Name: "SC3-CSP: zero CSP console violations on load"
   Action:
   - Collect console messages on the page
   - Navigate (testInPreview navigates in its wrapper — use a fresh page.on('console') listener BEFORE navigation, then navigate manually for this check):
     const violations = [];
     page.on('console', msg => {
       if (msg.type() === 'error' && msg.text().includes('Content Security Policy')) {
         violations.push(msg.text());
       }
     });
     await page.goto(page.url()); // re-navigate to capture load-time CSP errors
     await page.waitForLoadState('networkidle');
     expect(violations.length).toBe(0);
   Alternative simpler approach: listen for console errors matching 'CSP' or 'Content Security Policy' during the testInPreview navigation and assert none.
   Note: Use testInPreview for navigation, add console listener inside the pageFunc callback before any awaits. On Chromium the listener must be attached before navigation fires — attach it then trigger a reload: await page.reload(); await page.waitForLoadState('load');

4. SC3-FOUC — data-theme set on <html> before paint (THM-03):
   Name: "SC3-FOUC: data-theme present on <html> before paint when visualMode is stored"
   Action:
   - This test uses testInPreview but must set localStorage BEFORE the page navigates, so the pre-paint script (theme-init.js) fires with the value already present.
   - Inside the testInPreview pageFunc, FIRST call: await page.evaluate(() => localStorage.setItem('visualMode', 'dark'));
   - Then reload to trigger a fresh page load with the value already in localStorage: await page.reload();
   - On DOMContentLoaded, theme-init.js runs synchronously and sets data-theme before any stylesheet-dependent paint. We verify this by reading the attribute synchronously after reload:
     const theme = await page.evaluate(() => document.documentElement.getAttribute('data-theme'));
     expect(theme).toBe('dark');
   This is the standard proxy for "set before first paint" — the attribute is present in the DOM as-parsed, meaning theme-init.js ran before any layout/paint cycle.
   After the assertion, clean up: await page.evaluate(() => localStorage.removeItem('visualMode'));

5. THM-05 — color-scheme property set on :root (THM-05):
   Name: "THM-05: color-scheme matches active theme on :root"
   Action:
   - Set light theme via #btn-light
   - Read document.documentElement's computed color-scheme: page.evaluate(() => getComputedStyle(document.documentElement).colorScheme)
   - Assert result is 'light' or contains 'light'
   - Set dark theme via #btn-dark
   - Assert result is 'dark' or contains 'dark'

Use expect from the { page, expect } callback parameter — do NOT import expect from '@playwright/test' or from 'chai'. The testInPreview wrapper passes test.expect as the `expect` parameter.
