# Phase 3 — UI Design Contract

> Visual and interaction contract for the **Options & Auxiliary Surfaces** phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** Apply the Phase 1 token system to the options page (two-pane layout, INI editor, form controls, color picker, Config Hub, storage selector, settings list, extension API section) and the three auxiliary pages (supporters, credits, updated). After this phase, every surface is fully styled in both themes (THM-01). Remove remaining `.darkMode` class toggles from `options.js` and all residual inline `<style>` blocks from options/supporters/credits/updated.
>
> **Requirements covered:** THM-01, OPT-01, OPT-02, OPT-03, OPT-04, OPT-05, OPT-06, OPT-07, AUX-01.
>
> **No CONTEXT.md exists for Phase 3.** All decisions below are derived from upstream artifacts (Phase 1 UI-SPEC, Phase 2 UI-SPEC, REQUIREMENTS.md, ROADMAP.md) plus Claude's discretion on open layout questions.

**OPT-06 swatch rule (reuses Phase 2 D-01):** The `<input type="color">` outer element receives `border: 1px solid var(--color-border-input)` so that WCAG 1.4.11 (3:1 UI component contrast) is owned by the border, regardless of the stored fill color. This is sufficient for WCAG 1.4.11 compliance at the control boundary.

## Interaction States

### `.darkMode` Removal (HARD CONSTRAINT — Phase 3 scope)

Phase 1 UI-SPEC §5 states: "inline `<style>` blocks and the `.darkMode` class are removed per surface in Phases 2–3." Phase 2 removed the popup's inline `<style>`. Phase 3 must:

1. Remove all `.darkMode .X` CSS rules from the options/supporters/credits/updated inline `<style>` blocks.
2. Remove all inline `<style>` blocks from options.html, supporters.html, credits.html, updated.html — replace with `<link rel="stylesheet" href="css/options.css">` (options) and `<link rel="stylesheet" href="css/pages.css">` (supporters/credits/updated).
3. Remove the `.darkMode` toggle logic in `options.js` lines 195–198 and lines 220–222 — these add/remove `.darkMode` on `document.body`. After Phase 3, the pre-paint `theme-init.js` (Phase 1) sets `data-theme` on `<html>`; `options.js`'s `syncStorageRepo.set({ visualMode })` write (the storage write) is **preserved** because Phase 4 will wire the live `data-theme` writeback.

**Phase 3 → Phase 4 transitional UX regression (accepted):** After stripping `.darkMode` toggle from `options.js`, clicking a Visual Mode radio will write to `chrome.storage.sync` but produce **no immediate visual change** — the page must reload to apply the new theme. This is a deliberate, one-phase regression. Currently the page repaints immediately via `.darkMode` class toggle; Phase 4 (THM-02/THM-04) restores live update via `data-theme` write + `storage.onChanged`. Planner must call this out explicitly in the phase plan so reviewers do not flag it as a bug.

### Panel Show/Hide Toggles (PRESERVED — `options.js` contract)

`updateRemoteFieldsState()` in `options.js` toggles `element.style.display = 'block' | 'none' | 'inline-block'` on the following elements. These inline-style toggles MUST NOT be replaced with CSS class toggling:

| Element ID | Current toggle values | Note |
|-----------|----------------------|------|
| `#standalonePanel` | `'block'` / `'none'` | Playwright: options.spec.js |
| `#configHubPanel` | `'block'` / `'none'` | Playwright: options.spec.js |
| `#cancelConfigHubButton` | `'inline-block'` / `'none'` | — |
| `#connectConfigHubButton` | `'inline-block'` / `'none'` | — |
| `#disconnectConfigHubButton` | `'inline-block'` / `'none'` | — |
| `#reloadConfigHubButton` | `'inline-block'` / `'none'` | — |

All existing element IDs in `options.html` are preserved (no renames). Key IDs from SC5 explicitly preserved: `#awsConfigTextArea`, `#saveButton`, `#msgSpan`, `#configStorageSyncRadioButton`, `#configStorageLocalRadioButton`, `#textareaKeyCode`, all `#*VisualRadioButton` IDs, all `#configHub*` IDs, `#colorPicker`, `#colorValue`.

### Firefox Tab-Grouping Disable (PRESERVED)

`options.js` sets `autoTabGroupingCheckBox.disabled = true` and `parentElement.style.textDecoration = 'line-through'` inline when Firefox is detected. The inline `style.textDecoration` assignment is preserved in JS. Phase 3 adds no CSS class alternative for this state; the strikethrough remains a browser inline style.

### Focus Ring

The Phase 1 global `:focus-visible` ring (in `base.css`) applies to all form controls, buttons, links, and the color picker without modification. `options.css` must not override or weaken this rule.
