# Phase 2 — UI Design Contract

> Visual and interaction contract for the **Popup Surface** phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** Apply the Phase 1 token system to the popup — role list, filter, states (loading/empty/error), per-profile color swatch, and sidebar nav — within the 600×600 cap, in both light and dark themes. This is a **surface** spec; it does not re-declare token values. For the full design-token, typography, color, and spacing system see `.planning/phases/01-design-system-foundation/01-UI-SPEC.md` (LOCKED, inherited by this phase).
>
> **Requirements covered:** POP-01, POP-02, POP-03, POP-04, POP-05, POP-06.
> **Decisions locked in CONTEXT.md:** D-01 through D-07 (swatch rule, two-line item, sidebar reskin, state copy).

## Color

All color values are `var(--token)` only — no hex hard-coded in `popup.css`. Full token set in `01-UI-SPEC.md`. Popup-specific color mappings:

| Role | Light token → hex | Dark token → hex | Popup usage |
|------|-------------------|------------------|-------------|
| **Dominant (60%)** | `--color-bg-layout` → `#ffffff` | `--color-bg-layout` → `#161d26` | `body`, `#main`, `#noMain` background |
| **Secondary (30%)** | `--color-bg-dropdown-item` → `#ffffff` / hover `#f3f3f7`; divider `--color-border-divider` → `#c6c6cd` | `--color-bg-dropdown-item` → `#1b232d` / hover `#131920`; divider → `#424650` | Role list rows and hover, sidebar dividers |
| **Accent (10%)** | `--color-text-accent` / `--color-border-focus` / `--color-link` → `#006ce0` | → `#42b4ff` | Focus ring on `#roleFilter` and nav links; `#openOptionsLink` uses `--font-weight-bold` only (not accent color); "Open Configuration" CTA link in empty state (`--color-link`) |
| **Destructive / error** | `--color-text-status-error` → `#db0000` | → `#ff7a7a` | Not used in popup (no destructive action exists) |

**Accent reserved for (popup-specific):**
1. The tokenized `:focus-visible` ring on `#roleFilter` and sidebar links (`--color-border-focus`)
2. The "Open Configuration" CTA link in the "on AWS, no matching roles" empty state (`--color-link`)
3. The CSS-only spinner top border in loading state (`--color-text-accent` / `border-top-color`)

No other element uses accent color in the popup. Hover states use neutral `--color-bg-dropdown-item-hover`. `.roleListTitle` uses `--color-text-heading`, not accent.

**Popup chrome (hard constraints — do not change):**

| Property | Value | Reason |
|----------|-------|--------|
| `body` max-width | 600px | Browser popup cap |
| `body` max-height | 600px | Browser popup cap |

**Scrollbar:**

- Move existing `scrollbar-width: thin` from inline `<style>` to `popup.css` on `#roleList`.
- Move existing `::-webkit-scrollbar` / `::-webkit-scrollbar-track` / `::-webkit-scrollbar-thumb` rules from inline `<style>` to `popup.css`, updated to use `--color-bg-container` / `--color-border-divider` tokens for track and thumb. `color-scheme` (Phase 1) handles Firefox and Edge native scrollbars automatically; custom WebKit scrollbar styles are an additive Chrome/Edge enhancement.

## Component Inventory — Popup-Specific Shells

These are the popup-specific CSS classes to author in `popup.css`. Phase 1 `components.css` state shells (`.aesr-state-empty`, `.aesr-state-loading`, `.aesr-alert`, `.aesr-divider`) are consumed as-is without modification.

**Note on `.aesr-role-item`:** The Phase 1 `components.css` role-item shell uses `flex-direction: column` for a vertical card layout. The popup role list uses a **row** layout (swatch left, text column right). Rather than override `flex-direction` on the shell (which would break its contract for other surfaces), the popup's `<a>` anchor is styled directly with row flex in `popup.css`. The `__name` and `__account` children from `components.css` are reused as-is.

### Role List Item (Two-Line Layout — D-02, D-03)

Existing outer structure preserved. All `dataset.*`, `onclick`, and the inline `style="display:block|none"` toggle on `<li>` are unchanged (Playwright contract).

**New inner structure (DOM update in `create_role_list_item.js`):**

```
<li style="display:block|none">   ← inline style toggle PRESERVED
  <a href="#" title="…" data-profile="…" data-rolename="…" data-account="…"
     data-color="…" data-redirecturi="…" data-search="…" data-displayname="…"
     onclick="…">                 ← all dataset.* and onclick PRESERVED
    <span class="headSquare"></span>        ← PRESERVED class name; swatch rendered here
    <div class="aesr-role-item-text">       ← NEW wrapper for text column

      [<span class="aesr-role-item__account">{account id}</span>]  ← omitted when hidesAccountId
    </div>
  </a>
</li>
```

The `createTextNode(item.name)` flat text node becomes `.aesr-role-item__name` span. The `.suffixAccountId` span is replaced by `.aesr-role-item__account` span. No existing Playwright test selector targets `.suffixAccountId` directly — safe to rename.

### Swatch (.headSquare) — D-01, D-03

```css
.headSquare {
  display: inline-block;
  flex-shrink: 0;
  width: 20px;
  height: 20px;
  border-radius: var(--radius-badge);   /* 4px — see radius note below */
  border: 1px solid var(--color-border-input);  /* contrast-bearing border — see WCAG note */
  background-size: contain;
  background-repeat: no-repeat;
  background-position: center;
}
```

**Radius note:** CONTEXT.md D-03 references `var(--radius-xs)`, but Phase 1 does not declare that token. The closest Phase 1 token for a ~4px rounded-square swatch is `var(--radius-badge)` (4px). Phase 2 uses `--radius-badge` directly — no new token declared. If a future phase requires `--radius-xs` as a named alias it hoists it at that time.

**Swatch border token (D-01 / D-01a — WCAG 1.4.11):** Border uses `var(--color-border-input)` — light `#8c8c94` / white surface = 3.34:1 (PASS 3:1 UI), dark `#656871` / `#161d26` ≈ 3.03:1 (PASS 3:1 UI). D-01 requires "border owns contrast" for POP-06 AA compliance; `--color-border-divider` (`#c6c6cd`/`#424650`) fails 3:1 against their respective surfaces and cannot be used for this role. The fill hex is the stored profile value, never mutated; the JS `headSquare.style.backgroundColor` assignment in `create_role_list_item.js` is unchanged.

## Interaction States

### Show/Hide Contract (HARD CONSTRAINT — Playwright)

The `#main` and `#noMain` elements are toggled via `element.style.display = 'block' | 'none'` in `popup.js`. This inline-style toggle MUST NOT be replaced with CSS class toggling. The following Playwright selectors must survive unchanged:

| Selector | What it checks |
|----------|----------------|
| `#roleFilter` | Filter input ID unchanged |
| `#roleList li.selected` | Currently selected role row |
| `li[style*="block"]` | Visible role list items |
| `li:not([style*="none"])` | Role items not hidden |

Do not apply `display: none` or `display: block` to these elements via CSS classes.

### State Switching

Three states are injected into `#noMain` by `popup.js` (or using sub-containers toggled within it — executor determines exact strategy). Either way: the existing `style.display` toggle on `#main` / `#noMain` is preserved; no CSS class drives show/hide.

### Focus Ring

The Phase 1 global `:focus-visible` ring (`outline: 2px solid var(--color-border-focus); outline-offset: 2px; border-radius: var(--radius-focus-ring)`) applies to `#roleFilter` and all `.optionMenu a` links without modification. `popup.css` must not override or weaken this rule.
